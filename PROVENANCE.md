# Provenance

This document records, for every shipped model artifact in **NativeUIAuditKit** /
**NativeUIAuditKitModels**: the training hardware, the exact hyperparameters, the source
datasets, and an explicit audit of those datasets for personal identifiers or proprietary
third-party assets.

It exists so a downstream consumer (or a future maintainer) can answer "what went into this
`.mlpackage`?" without reconstructing the answer from chat history. See also
[`Research/LicensingArchitecture.md`](Research/LicensingArchitecture.md) for the license/IP
boundary between the MIT-licensed code and the AGPL-3.0-derived YOLO11 weights.

Last updated: 2026-09-18.

---

## 1. Training hardware

All training in this repository runs locally on Apple Silicon, using PyTorch's MPS backend
(Ultralytics YOLO runs) or Create ML (retired, pre–Run 006 only). Specific runs recorded the
exact chip where noted below; where a run's log doesn't name the chip, assume the same Apple
Silicon MPS host used throughout `Research/ExperimentLog.md`. No cloud training, no third-party
compute, no distributed/multi-node training has been used for any shipped model.

## 2. Shipped models — exact configuration

Each entry links to its full record in [`Research/ExperimentLog.md`](Research/ExperimentLog.md).
Hyperparameters below are what actually shipped, not every configuration tried.

### `nativeui-ios-v2.0` (iOS/iPadOS 5-class detector)

- **Run:** [Run 006](Research/ExperimentLog.md) — YOLO11n migration, complete 2026-08-23
- **Architecture:** Ultralytics YOLO11n, 100 epochs, anchor-free head
- **Training set:** 20,632 annotated images (same set used for Run 005)
- **Export:** `coremltools` 9.0, FP16, NMS baked into the CoreML graph (IoU 0.30, confidence floor 0.001)
- **Result:** mAP@0.5 = 0.935 (CoreML) / 0.968 (raw `.pt`); latency ~7.5–9 ms/image on-device
- **Classes:** `alert`, `navigationBar`, `primaryButton`, `textField`, `toggle`

### `nativeui-tvos-v3.0` (tvOS 25-class OS UI detector, current default)

- **Run:** [Run 012](Research/ExperimentLog.md) — Phase 6b-E extended, 2026-09-16
- **Architecture:** Ultralytics YOLO11n, 25 epochs, batch=16, imgsz=640, device=MPS (Apple M4)
- **Training set:** 5,000 synthetic tvOS images (1920×1080), 200 per family across 25 UI-surface families, generated by `scripts/generate_tvos_dataset.swift`
- **Export:** `coremltools`, FP16, NMS baked in — `NativeUIModel_tvOS.mlmodelc` (5.2 MB)
- **Result:** mAP@0.5 = 0.9822, mAP@0.5:0.95 = 0.944
- **Superseded runs retained for backward compatibility:** `nativeui-tvos-v1.0` (Run 010, 10-class, mAP@0.5=0.995 on a narrower test set), `nativeui-tvos-v2.0` (Run 011, 21-class, mAP@0.5=0.971)

### `FocusRingDetector` v0.1 (tvOS Stage-2 focus classifier)

- **Run:** [Run FDR-001](Research/ExperimentLog.md) — complete 2026-09-18
- **Architecture:** MobileNetV4-Conv-Small (vendored `scripts/focus_ring_backbone.py`; no `timm` runtime dependency), 256×256 RGB input, sigmoid output, batch 64, 30 epochs, lr 3e-4
- **Training set:** 1,500 focused/unfocused crop pairs harvested from the `TVTestRigFixture` test-harness app via `scripts/harvest_focus_pairs.py` (split: 1,201 train / 164 val / 135 test, `recipe_seed`-disjoint)
- **Export:** `torch.jit.trace` → `coremltools` 9.0, FP16 — `FocusRingDetector.mlpackage` (4.80 MB)
- **Result:** held-out test accuracy 100%, FPR 0%, FNR 0% (270/270); hard-negative gate is currently vacuous (n=0 — no `light`/`highContrast` theme pairs collected yet, tracked as [FOCUS-DET-05](Tasks.md))

### 41-class full-taxonomy detector — **not shipped**

Phase 6a's 41-class YOLO11m model (Run 009) has **not** cleared its promotion gate (DS-G8,
mAP@0.5 ≥ 0.850 on withheld-template holdout) and is not bundled in
`NativeUIAuditKitModels`. Current best: mAP@0.5 = 0.586 on the synthetic withheld-template
holdout. Tracked in [Tasks.md](Tasks.md) as TASK-6a-10/11/12.

## 3. Source datasets

| Dataset | Nature | Used for | Committed to git? |
|---|---|---|---|
| SwiftUI/UIKit synthetic generator output (`NativeUIDatasetGenerator`, `GeneratorRunner`) | Procedurally rendered iOS/iPadOS screens; all text from a seeded fake-content corpus (`ContentCorpus.swift`) | iOS/iPadOS training (all runs through Run 009) | No — lives in the external `NativeUIAuditKit-Dataset/` store, not this repo |
| tvOS synthetic generator output (`scripts/generate_tvos_dataset.swift`, 25 SwiftUI templates) | Procedurally rendered tvOS screens (Home, Settings, Control Center, AVKit, etc.); no real device or account data | tvOS training (Runs 010–012) | No |
| `TVTestRigFixture` crop pairs (`dataset/tvos_fixture_captures/`) | Screens from a custom, purpose-built test-harness app (`TVTestRigFixture`) — accessibility/audit/component probe scenes, not real Apple TV OS UI | FocusRingDetector training (Run FDR-001) | No — `dataset/` is fully `.gitignore`d |
| Real Apple TV hardware captures (`dataset/tvos_captures/`, device "office") | Live screenshots from a real, personally-owned Apple TV 4K, mostly Home Screen / App Switcher / fixture-launch surfaces | **Evaluation and qualification only** (Phase 6b-R hardware qualification) — never used as training input to any `train_*.py` run | No — `.gitignore`d, zero commits (`git ls-files dataset/` returns empty) |

**No dataset used for training any shipped model has ever been committed to this repository.**
`dataset/` is listed in `.gitignore` (line 85) and `git ls-files dataset/` confirms zero tracked
files. The only redistributed artifacts are the compiled `.mlpackage`/`.mlmodelc` weights
themselves, via `NativeUIAuditKitModels`.

## 4. Personal-identifier and proprietary-asset audit

### Training data: clean — verified

- `dataset/focus_ring/focus_dataset_manifest.json` (all 1,500 FocusRingDetector pairs): every
  entry's `fixture_scene` field is `"TVTestRigFixture"`. Filenames and manifest contents were
  searched for `about|network|profile|account|mac|email` — zero matches. This dataset never
  touched a real Settings/About/Network/Profile screen.
- `dataset/tvos_fixture_captures/` (source crops for the above): all 45 files are
  `accessibility_*`, `audit_*`, `components_*`, or `tab_*` fixture-app probe scenes — same
  audit, zero matches.
- `dataset/tvos_captures/` (real "office" Apple TV captures, `office_*` prefix): used only for
  Phase 6b-R evaluation, never training. Filenames audited for
  `about|network|profile|account|mac|email` — zero matches; these are Home Screen / App
  Switcher / fixture-launch captures, not deep Settings screens.
- No SwiftUI/UIKit or tvOS synthetic generator template renders real user data — all generator
  text comes from `ContentCorpus.swift`'s seeded fake-content corpus.

### Evaluation/documentation artifacts: **not clean — open finding**

An audit of `reports/` (tracked in git, **already pushed to the public GitHub repo**
`SerialForBreakfast/NativeUIAuditKit`) found real personal-network identifiers belonging to the
repository owner, captured during the tvOS Settings RCA session
(`reports/tvos_navigation_rca_and_safety_architecture.md`) and its supporting exports:

| File | Contains |
|---|---|
| `reports/tvos_navigation_rca_and_safety_architecture.md` | Home IP `192.168.1.14`, personal email `joseph.mccraw@cbsi.com` |
| `reports/tvos_settings_complete_tree.json` | Same IP, same email (truncated) |
| `reports/tvos_settings_hierarchy.json` | Same IP, MAC address `34:fd:6a:02:b8:41`, router IP |
| `reports/tvos_settings_interactive_map.html` | Same IP, same email, device name "office" |

**This is not training data** — it is OCR/crawl exploration output and a narrative RCA
document, never referenced by any training or export script (`grep` confirms no
`scripts/*.py` reads from `reports/tvos_settings_*`). It does not affect the provenance of any
shipped model. But it is real personal information, currently public, in a public repository.

**Status: redacted in place, 2026-09-18.** The maintainer chose in-place redaction over a
history rewrite (explicitly deferring the history question as a separate decision). All four
files above had their real values replaced with placeholders
(`<REDACTED_IP>`, `<REDACTED_ROUTER_IP>`, `<REDACTED_MAC>`, `<REDACTED_EMAIL>`,
`<REDACTED_NAME>`, `<REDACTED_SERIAL>`, `<REDACTED_DEVICE_UDID>`) and verified clean by
re-grepping for the original IP, MAC, email, name, serial number, and device UDID strings —
zero matches remain in the working tree.

**This does not remove the real values from prior commits.** They are still present in this
repo's git history (and on GitHub, in the commit that introduced them) until/unless a history
rewrite is separately performed. That remains an open, explicit decision — not scheduled.

Going forward: be considerate about what real device/account data ends up in anything destined
for `reports/` or `Research/` — those directories are git-tracked and, for this repo, public.
Real captures belong in `dataset/` (`.gitignore`d) or should have identifying values redacted
before being copied into a tracked file.
