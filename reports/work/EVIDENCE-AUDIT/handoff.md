## What the pasted implementation did—and did not—prove

1. Its inventory is useful, but `is_file()` did not verify all PNG contents or
   establish label correctness. The new audit decodes every declared crop, records
   dimensions/mode, and hashes bytes plus normalized RGB pixels.
2. Zero shared recipe seeds was called clean leakage. The actual corpus has **84
   identical-pixel groups crossing splits**, totaling **386 crop references**:
   40 train/validation, 25 train/test, 15 train/validation/test, 4 validation/test.
   Across the whole corpus 172 pixel groups repeat; one has both focused/unfocused
   labels. Exact pixel matching still cannot exclude related-journey/near-duplicate
   leakage. The old held-out 270/270 result is not independent quality evidence.
3. The supplied PER-04 report validated an empty, constructed manifest. It did not
   ingest the legacy corpus or test real physical crop/frame lineage. The metadata
   helper could return eligible=true for nonexistent files. It now explicitly
   reports metadata-only, integrity-unverified, eligible=false and rejects nonhex hashes.
4. The supplied PER-02 report is one testOnly case with unavailable predictions and
   no byte verification. It is a missing-adapter response, **not a measured baseline**.
   Rerunning five tests did not implement the missing adapters/slice reporting.
5. The evaluator's n=0 hard-negative report could pass, missing crops were silently
   filtered, and reports could overwrite old results. The extant FDR-001 reports
   still have 2026-09-18 timestamps; the pasted command is not evidence of a fresh
   successful evaluation. They remain untouched as historical artifacts.

## Implemented corrections

- Reusable audit CLI preserves every requested member/failure, hashes decoded pixels,
  normalizes val/validation, reports cross-split content independently of seeds,
  excludes prediction files from annotations, and refuses output collisions.
- Legacy evaluation validates complete membership before model loading, rejects
  cross-split content/seeds, invalid/missing probabilities and silent shrinking.
  One explicit backend is required; no fallback or implicit report destination.
  Output directory must be new and inside the package. Torch checkpoint loading uses
  weights_only=True. Imports no longer create cache directories.
- Empty hard negatives produce null FPR and no pass; ≥100 examples and all four
  required strata are necessary. Legacy diagnostics require an explicit flag and
  cannot pass model gates. Numeric qualification requires the existing strict v1.3
  contract, quota validation and reviewed corpus membership; it is not promotion.
- Perception CLI requires hash/decode/dimensions for every real-source case, even
  without --verify-bytes. Nonfinite/boolean boxes fail. Unknown semantics are counted
  as semantic abstentions, not destructive-as-informational errors.
- Physical metadata inspection no longer asserts eligible data. Full frame-backed
  physical integration is deliberately still a PER-04 requirement, not marked done.
