# Public research source and local evidence

The research scripts and documents preserve investigations, including failed approaches.
Their presence does not approve execution or establish model accuracy.

## Execution requirements

- Use reviewed inputs with the required hashes and data roles.
- Set the actual host owner before creating a new experiment specification.
- Qualify the target before capture. Public host aliases are not enrolled worker identities.
- Review paths and volume identifiers before migration or storage operations.
- Use explicit approval for each immutable job. Do not run historical registration scripts to refill a queue.
- Keep original receipts when a successor replaces a failed experiment.

Some scripts use retained local inputs that do not ship with this repository.
Missing inputs are a requirement to resolve, not permission to substitute data.
Migration tools default to paths beneath the current user's home directory.
They still require the configured volume and verification checks.

## Evidence limits

Historical result documents retain their original counts and limitations.
This publication does not repeat inference, reopen an audit set, or promote a model.
Consult the applicable review before using a historical conclusion.
Earlier proposals can be superseded by later findings.
References in historical plans are not newly verified by this publication.

Raw captures, checkpoints, transport receipts, and work logs remain local.
Public host aliases distinguish the research host, peer host, and worker host.
They do not establish a live reporting connection.

## Running experiments

The runner checks exact source hashes.
Do not replace a pinned source file while an approved job still needs it.
Sanitized public copies can differ from retained execution copies.
Apply those changes at a safe boundary and create new approvals when required.
Do not hide these differences with Git index flags or weaken the source checks.
