## What changes now

An investigation includes its producer, qualification, fit, comparisons, decision, and approved follow-ups.
The detached runner executes approved jobs.
Conditional diagnostics do not require another conversation.
An invalid input stops its dependent branch, not other approved work.
No branch promotes a model.

Two iOS campaigns reuse `detector_training_batch478.py`.
Each description supplies admitted membership, initialization, and retained baseline jobs.
The compiler preserves evaluation inputs and settings.
It creates training, 6 comparisons, one decision, and 6 conditional class-confusion diagnostics.
The diagnostics run only when the decision reports a lost retained success.
Supported and inconclusive decisions stop training and report the next requirement.

This compiler complements the existing crop and full-screen focus compilers.
It does not replace the queue or add a scheduler.

## Bounded result rules

| Result | Executable action | Stop condition |
|---|---|---|
| Retained detection is lost | Run the fixed class-agnostic diagnostic for each matched evaluation set | Publish case-linked class and geometry errors. Do not start another fit. |
| Gains occur without losses | Publish the comparison and independent qualification requirement | No automatic promotion or more training. |
| No gains or losses occur | Publish an inconclusive decision | Require new evidence before another correction. |
| Capture restoration fails | Preserve the guard, frames, and journals | Qualify restoration-only recovery. Do not repeat complete captures. |
| Labels are incomplete | Use the qualified producer correction when available | Verify the corrected contract before training admission. |
| A frame has uncertain or clipped labels | Exclude the complete frame and record its identity | Do not teach the unlabeled object as background. |
| Evidence hashes or schemas fail | Preserve the failed attempt and name the exact requirement | Create an explicit successor. Never relax the submitted specification. |
