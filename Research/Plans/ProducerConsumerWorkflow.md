# Producer/consumer workflow alignment — October4

Adopt the maintainer's five improvements as coordinated work, not evidence that
new commands already exist. NUIAK owns acceptance/admission and reusable consumer
contracts; TTR owns its coordinator, rendering, workspace and source integration.
This plan grants no new device, Git, capture or promotion authority. No speed/token
savings claim until measured. Current request is adoption/alignment, not completion.

## FLOW-VALIDATE — shared contract checks first

FLOW124 supplies a test-only harvest-compatibility-v1 conformance pack using the
existing H1and sidecar-v2constructors and real consumer validator. These are not
genuine captures, and this pack does not cover every newer producer feature or
prove production crop parity. Every case declares expected pass/failure with
observed typed reason and exact content hashes. Source hashes pin validator and
fixture revisions. Pair this with sanitized COVERAGE119exposure metadata:282known
training-exposed images, no reserved independent-final membership. Absence from
this inventory is unknown, not permission to assign a new image to final evaluation.
Native body-conflict vectors and actual runtime crop parity remain separate
extensions once producer contract/source evidence is aligned.

Inputs: exact producer/consumer source revision, schema/validator version and small
positive/negative corpus. Reuse `harvest_sidecar_v2`, existing bundle/geometry checks,
and actual runtime preprocessing. Do not maintain a permissive parallel validator.
TTR may invoke pinned local checks or conform against the same versioned vectors;
NUIAK intake rechecks received bytes. Return typed reason, exact artifact/case,
expected/observed values, contract revision and supported check scope.

Separate bytes/completion, annotations/geometry, source evidence, coverage and
split ancestry from training admission. TTR can prove ancestry only against its
supplied inventory; absent NUIAK exposure registry means global leakage unknown,
not passed. Same-pixel conflicts compare the same element, coordinate space,
viewport and annotation semantics/version: body boxes and focus outlines are not
interchangeable. Preserve both conflicting records; never average or silently pick.
Coverage expectations are frozen per requested task, not inferred from present data.

Preprocessing is model-specific: FocusRing uses production16%expanded256×256crops;
DTM change-only uses paired full-frame192×128letterboxing. One crop validator must
not apply FocusRing rules to every model. Prediction output is never label authority.

Tests: completed/partial bundles, missing/corrupt/changed image, malformed/unknown
schema, inconsistent same-element geometry, label-source violations, duplicate
content and ancestry leakage, unsupported classes, missing registry. Acceptance:
positive vectors agree across producer/consumer; deliberately invalid corpus
returns the same case-bound reasons. No training eligibility granted by these tests.
Next: attach checks to existing producer jobs, then qualify one authorized real job.

## FLOW-GENERATE — one resumable existing-job workflow

Reuse current Fixture jobs and campaign plan/generate/resume APIs; do not invent
`aatv synthetic generate` as an existing interface or add a second coordinator.
Resolve exact target, runtime/build, endpoint, recipe/catalog hash, output owner and
granted workspace access before mutation. Prepare once per compatible campaign;
retain bounded batches/health checks, not repeated simulator setup per recipe.

Checkpoint immutable completed members and per-attempt failures. Resume only
missing planned groups after checking actual job terminal state, owned resources,
current input identities and cleanup. If source/config/schema changes, create a
new compatible version or fail explicitly. Do not repeat ambiguous mutation or
reuse successful output blindly. Publish completion only after manifest/integrity
and postflight pass. Preserve partial output and capture original telemetry.

Tests: request-only no mutation, wrong target/access, output collision, interrupted
job with retained successful members, changed config rejection, cleanup failure.
Acceptance: one authorized generated job and interrupted resume prove no recapture
of completed members; returned local manifest is independently accepted. Headless
operation does not bypass app coordinator, sandbox, permissions or resource leases.
NUIAK source-first local generation remains independent of Sillycon and complementary
to physical captures, real failure reproductions and backups—not a transfer replacement.

## FLOW-TRANSFER — deterministic receipt reconciliation

FLOW-TRANSFER123 implements a narrow file-transaction CLI, not a general sync tool.
JSON transaction v1 pins requestID, shared relative path, project-local original or
receive destination, byte count/SHA256 and optional peer receipt path. Read-only
inspection is default; --execute is required for selected publish/receive/cleanup.
Mount is verified freshly; source and parent path symlinks/traversal are rejected.
Publication uses deterministic staging and macOS renamex_np(RENAME_EXCL), confirmed
in the resident SDK, so an existing destination cannot be overwritten. Incomplete
staging remains evidence and blocks retry; complete exact staging can resume.
No unpacking is performed: archive inspection/admission remains an independent
existing intake step. Receiver output is a compatible exact-byte receipt, not
dataset approval. NUIAK deletion applies only to its own shared copies with exact
peer receipts, current bytes and verified retained original. An already absent
shared file is reported as absent, never fabricated as newly deleted by this run.

NUIAK owns a local tool for its namespace; TTR owns its equivalent/use. Inputs:
verified expected mount, exact transaction ID, namespace/path, bytes/hash, original
and receiver receipt. Default inspect/dry-run; explicit named publish/receive/cleanup
operations. Existing retired whole-file status synchronizers must not be revived.

Unique staged publication, final byte readback, bounded safe extraction and receiver
receipt are separate outcomes. Sender cleanup requires matching transaction/path/
bytes/hash receipt AND current shared bytes AND retained original verification.
Never delete by expiry, directory glob, stale status, filename alone or ack alone.
Idempotent retry reconciles observed state; ambiguous outcome preserves evidence.
No mounting, SSH, permission weakening or unapproved artifact transfer in the tool.

Tests: valid receipt, wrong hash/size/request/path, traversal/symlink, missing mount,
publication interruption, duplicate receipt, mismatched changed file, cleanup after
already-completed exact transaction, insufficient space. Acceptance: deterministic
results and exact safe cleanup; unresolved transactions never silently disappear.

## FLOW-STATUS — compact current view and review-ready source handoff

FLOW125 implements a read-only CLI: `status` projects each packet plus every
nonempty pending-request/blocker collection with its JSON pointer and input digest;
`git` inventories porcelain-v1 NUL records and validates an explicit intended-file
list. Unknown fields remain recoverable through the pinned source, not discarded
from the stored board. Output is stdout for project-local redirection, never an
automatic shared-file rewrite or archive. Missing/invalid timestamps mean unknown.
Test results supplied to handoff are reported assertions, not fabricated executions.

Generate a current view from namespace-owned records: active task, blockers, next
owner/action, outstanding requests, changed evidence and separate four outcomes.
Keep timestamps/expiry per entry. Archive resolved history with durable references;
preserve unresolved requests and unknown fields. No arbitrary line/age deletion,
stale whole-file writes or claims that SMB is a lock/transaction queue.

Generate read-only Git handoff: exact base/head and dirty state, changed/untracked
file inventory, intended task subset, tests/commands/results, consumer uptake need
and proposed commit message. Include scripts/tests/contracts, not just one app folder.
Never run Git writes or offer broad add commands including unrelated/private data.
Maintainer reviews exact paths and performs Git operations.

Tests: concurrent unrelated packet update, unresolved old request, duplicate keys,
unknown fields, absent share, dirty/untracked/excluded paths, stale evidence.
Acceptance: compact view loses no actionable request; handoff maps every intended
file/test and identifies what NUIAK needs from that revision. No source publication
or consumer integration implied by writing a summary.

## Shadow feedback and measurement

Automatic case-linked feedback remains optional/passive: original action/observation/
image hashes, actual loaded model/version/backend, score/abstention/failure, queue
drops and timing. Join separately reviewed labels afterward. No navigation waits,
authority, self-labeling or automatic replacement. Preserve DTM025/030 comparisons;
survey24and26mixed native-hint reports are not a promotion argument.

Measure accepted examples/hour with separate integrity-compatible and training-
admitted counts, end-to-end elapsed time, setup/capture/audit/transfer/wait durations,
operator interventions, retry/recapture count and rejection reasons. Report batch
sizes, source versions and first/warm/resume runs. Benchmark equivalent workloads;
avoid claiming model improvements from faster preparation or accounting changes.

First integrated qualification: agreed validation vectors + deliberately invalid
corpus; one authorized genuine generation + interrupted resume; transfer mismatch
and partial-publication tests; compact status preserving unresolved work. TTR
acknowledgment/source-backed capability inventory identifies existing features and
actual gaps before implementation is duplicated.
