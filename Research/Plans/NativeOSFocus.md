## OS-FOCUS-03 — Deterministic Home-screen coverage

User-requested extension, 2026-09-22. Home is an explicitly scoped native OS
surface, not an escape from Settings. Reuse the independent XCTest observer and
production crop path; do not depend on TTR or Fixture. This contract does not
claim the existing Settings-only probe implements Home traversal.

### Inputs and authority

- Exact simulator/runtime and runner build, fresh exclusive-use check, observed
  Home identity and layout fingerprint; no inferred launcher bundle identifier.
- Installation/runtime-storage approval for the independent runner remains pending.
  Home traversal is requested; once runtime authority is resolved, entering Home
  is labeled setup, not an inferred Settings-to-Home navigation success.
- Only single directional taps. No Select, long press, app/folder launch, icon
  rearrangement, account changes, installs, purchases or physical-device fallback.
  A modal, edit mode, app launch or unknown context stops the run; no automatic
  dismissal or takeover. Top Shelf is separately identified, not assumed a grid row.

### Implementation

1. Extend the runner with an explicit Home mode; preserve the Settings mode.
   Observe native focused identity, visible item geometry and viewport/scroll
   state. Reject ambiguous duplicate identities; position alone is insufficient
   across scrolling. Bind a reproducible plan to the observed layout fingerprint.
2. Build an observed directional graph. Nodes are stable items in a layout;
   edges record source, direction, destination, viewport changes and evidence.
   A stable same-item result is a boundary/no-op observation, not a successful
   transition or automatically a test failure. Missing focus is not a boundary.
3. Generate deterministic horizontal snakes (both starting sides), vertical
   snakes (both starting ends), and reverse traversals. Reobserve after every
   input; route to start nodes through verified edges and count repositioning.
   Handle ragged rows, scroll exposure and directionally asymmetric edges.
4. Generate clockwise/counterclockwise inward spirals only for verified rectangular
   regions. Reverse those paths for outward coverage. Missing cells or nonlocal
   directional moves produce an explicit unsupported spiral, not invented neighbors.
5. Exercise each reachable item's four directions, plus feasible length-two
   direction pairs: reversals, repeated directions and right-angle turns. These
   16 direction pairs are coverage goals, not an instruction to send blind macros.
   Use canonical ordering and a frozen seed only to resolve documented ties.
6. Initial live segment: at most 40 directional inputs and five minutes, with
   five-second observation operations and ten-second settling limits. Later
   segments resume a compatible journal after fresh target/layout/focus checks;
   no resume across uncertain input or cleanup. A budget stop retains a frontier
   rather than claiming full coverage. No automatic unbounded sweep.
7. Record intended/observed transitions, distinct items, directed edges, boundaries,
   direction-pair support, unseen frontier, scrolls, missing labels, capture/settle
   latency and invalid trials. Report coverage against the discovered graph, not
   an unproven inventory of every installed app or all possible OS states.

### Training evidence and efficiency

Capture settled full frames with bracketing native focus/geometry and measured
pixel scale. Pair the same visually reviewed item while focused and unfocused;
preserve actual bounds in each state. Clipping, scaling, adjacent-item glow,
scrolling and Top Shelf/background changes receive explicit strata. Requested
navigation and model guesses never become focus truth.

Traversal repetition primarily improves transition validation; it does not make
identical pixels new independent training examples. Retain transition evidence,
deduplicate training samples with exact pixels/lineage, and report unique pairs.
Never deduplicate away the intentional focused/unfocused distinction. Keep all
related sessions for the same layout/content lineage together; random frame splits
would leak nearly identical app icons. New layouts/themes require separate approved
configuration changes, not icon rearrangement during this run. Native Home cannot
alone establish general custom-control or physical-tvOS coverage.

Do not require global pixel equality for animated backgrounds. Native focus and
geometry stability plus reviewed local focus-region evidence govern admission;
transition frames stay separately labeled, not mixed with settled focus examples.
Retain raw evidence locally and privacy-review account/recommendation content.

### Tests, acceptance and next action

Offline planner tests: rectangular and ragged grids, single row/column, missing
cells, asymmetric moves, repeated labels, no-op edges, scroll/reflow, deterministic
replay, budget exhaustion, changed layout and interrupted-input rejection. Test
